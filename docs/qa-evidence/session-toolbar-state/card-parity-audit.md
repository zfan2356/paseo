# Session card parity audit

基准：fork main `4695cf5ae`；审计界面：PR #15。行号以 `8d2d0a587` 定位；最终修订见 PR。这里的“旧/新”指保留的 workspace 卡片与 session 界面，不是 PR #15 的逐项 before/after；这些缺口多数已在基准存在。历史迁移回归归因仍需迁移前精确修订。这是调用链静态审计；浏览器证据只覆盖工具栏与实时状态用例，不把未操作的菜单或快捷键标成已验证。

现有新行没有对齐旧卡片的交互。归档 RPC 存在，但原来的一次点击归档入口已消失；重命名和读状态操作缺失；pin/标签被藏进设置。旧组件同时承载工作区操作，不能把整个旧工作区控制器绑定到会话。

## 建议 Root 收敛的最小修复

1. 当前 PR 的工具栏和独立状态先按原两项审查。卡片层优先恢复会话菜单：重命名、直接 pin/unpin、直接标签入口、标为已读、归档；恢复 pointer hover 的一次点击归档和 web 右键。复用原尾部视觉、ContextMenu/DropdownMenu 和标签视觉，菜单项共享回调，不复制一套“简化菜单”。
2. 归档先复用已有 agent hook 并明确当前 tab/焦点、history 和失败回滚；不另造生命周期。控制器使用显式会话 target `{serverId, agentId}`。已有 workspace 控制器继续拥有工作区归档/worktree 风险、名称、未读和资源。不要为复用旧组件而构造一个假的 workspace，也不要把 agentId 填进 workspaceId。
3. 标签创建/选色、会话标为未读、会话命令作用域、普通会话手动排序/拖动与移动长按，由 Root 单独定范围；已有 SDK 不能直接支持会话 mark-unread。先不改协议，也不以工作区 API 代替。
4. 目录复制、外部打开、Git/终端/服务摘要留在资源层；会话显示必须标出具体目录或明确跳转。归档工作区或删除 worktree 不进入会话归档动作。

本审计不授权上述新增实现。实际接线、离线行为和快捷键仍须相应浏览器/平台验证；当前通过的聚焦截图不能证明菜单功能全面对齐。
