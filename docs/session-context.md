# 会话导航与上下文设计

状态：WORK-365 的统一设计已确认。会话是唯一主行；项目沿用现有根目录项目，允许会话手动换项目；删除全局会话/路径开关；执行目录切换另立项；绑定不保活 worktree；PR #10 不原样合入。

本文描述目标设计，界面线框和后续切片尚未全部实现。WORK-366 只交付 daemon 存储、协议、SDK、目录手动绑定与初始化；不改界面、执行 cwd、workspaceId 或工作区项目外键，不做 worktree 自动绑定。持久化约束以 [data-model.md](data-model.md#session-context) 为准，协议约束以 [protocol-compatibility.md](protocol-compatibility.md) 为准。

设计依据：WORK-365（已验收），承接 WORK-328、WORK-362、WORK-364 的调研；代码证据描述设计时的现状，目标行为见各节。

## 1. 从四个场景看完整流程

| 场景                                   | 现状与原因                                                                                                          | 新设计下用户看到、做到什么                                                                                                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 从 `~/works` 开“slime 与 gmi 联调”会话 | 启动目录不是 Git 仓库。按 cwd 取 Git 的表面没有目标；将会话 MR 接到工作区行也没有解决跨目录导航                     | 在 works 项目下只有一条“slime 与 gmi 联调”。展开能看到启动目录、手动绑定的 `~/works/slime`、`~/works/gmi` 和两个仓库的 MR。点 slime 打开 slime 文件树/本地更改；点 gmi MR 打开该 MR。会话和执行目录仍是原对象，输入框继续向原会话发送。 |
| 两个 gmi 会话共用一个目录              | 工作区行从 checkout 取分支、MR、改动量；#10 在同工作区有多个候选会话时不显示会话 MR。两种做法都没有表达两个独立会话 | 两条会话行各有自己的标题、状态与关联 MR；展开后都可出现同一条 gmi 路径。两处本地更改内容相同，并说明它属于该目录。会话 A 的 MR、草稿和选择不会变成 B 的；本地未提交内容不归给任何一个会话。                                             |
| 会话创建 worktree 并提出 MR            | 会话 MR 已有持久关联；worktree 创建主要携带 workspace 上下文，不能据此自动归给其中一个会话                          | 新目录在成功且可核实发起会话的操作后加入该会话，侧边栏立即可进入；MR 成功登记后成为同级子项。目录与 MR 互不要求一一配对。创建目录不切换已有会话 cwd；若选择“在此新建会话”，新会话有自己的行、启动目录和父子关系。                       |
| 只读调研会话                           | `~/works` 的空 Git 状态容易被理解成没有工作；强制创建 checkout 或拼出“会话更改”都不符合任务                         | 会话正常显示标题和活动状态，展开可浏览资料目录；无 MR 时不显示 MR/增删量，不猜仓库、不扫描 `~/works`。未绑定其他目录也能完整聊天。这里的“调研”是使用场景，不新增一个能保证只读的权限模式。                                              |

这四种流程共用同一套导航；不要求先选择“会话模式”还是“路径模式”。

## 2. 概念模型、数据归属和生命周期

先纠正一个会影响实施的事实：**当前 workspace 不是目录的别名**。它有独立 opaque ID，并拥有 agent、terminal、布局和清理关系；多个 workspace 可以共用同一 cwd。`workspaceId` 与 `cwd` 不能互换，也不能直接将一个工作区“改名成目录”后删除它的身份。

代码依据：`packages/server/src/server/agent/agent-storage.ts` 的记录含 agentId、单个 cwd、可选 workspaceId、title、timestamps；`packages/protocol/src/messages.ts` 的会话快照同样有这些信息。`:4150` 的工作区 descriptor 有 projectId、pinnedAt、labels 和 checkout 状态。`packages/app/src/hooks/sidebar-workspaces-view-model.ts` 将这些投影成工作区行。`utils/workspace-agent-activity.ts` 还会为工作区选取最近活动的根会话，所以现有行并不是“一行等于一个会话”。

采用以下词汇和归属；术语定义见 [glossary.md](glossary.md)；以下说明目标模型与数据归属。

| 概念           | 定义与身份                                                            | 保留、调整及归属                                                                                                                                                                                                                                                   |
| -------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 会话           | 一个已有的 durable agent/conversation；客户端键 `(serverId, agentId)` | 升为主要导航对象。沿用 agentId，不再造 conversation/task 聚合 ID。拥有自己的标题、活动/关注状态、项目分组、置顶、标签、目录关联、PR/MR 关联及浏览选择。provider 重连不换身份；fork 是新会话。                                                                      |
| 启动目录       | 创建会话时记录的执行位置                                              | 保留为会话的历史事实。总在目录列表首位，不能移除；不存在时显示失效。不是“会话只会改这里”的承诺。                                                                                                                                                                   |
| 执行目录       | provider 后续执行所用的 cwd                                           | 当前与启动目录相同，保留单值 `agent.cwd`。未来若支持切换，也只更改执行配置，不覆盖启动历史。不是浏览器当前打开的目录。                                                                                                                                             |
| 绑定目录       | 会话明确关联的一处 daemon 本地绝对路径                                | 与会话多对多；绑定本身不拥有文件，不扩大文件/agent 权限。用户文案采用“目录”，是本设计对现有禁止该词的 glossary 规则的有意替换。目录是文件/本地 Git 的入口，既可非 Git，也可落在同一 checkout 的不同子目录。                                                        |
| PR/MR          | 按 forge、host、完整 projectPath、number 唯一寻址的远端更改请求       | 保留 WORK-328 身份与关联来源。会话拥有关联，远端内容由 forge 持有。用具体 forge 的 PR/MR 名称；不把整份 diff 称为会话创作。多个会话可以关联同一项。                                                                                                                |
| 项目           | 会话的稳定分组                                                        | 保留现有 host-local projectId 和 opaque projectKey；暂不新增无路径项目体系。新会话在项目入口创建时明确选项目；已有会话初始取 owning workspace 的项目。启动目录只提供初始，绑定目录不自动重分组。允许用户把会话移到另一个现有项目，与 workspace 的 projectId 分开。 |
| 工作区         | 带单个 cwd 的内部执行/资源容器                                        | 从常规导航、会话创建文案中降级；workspaceId 继续承担现有 agent/terminal/布局/清理关系，FK 不改。它可以含多会话，不能再当作会话行身份；不能通过绑定路径生成 N 个 owning workspace。                                                                                 |
| 分支、worktree | 路径的 Git 事实与隔离资源                                             | 分支不再作为会话标题来源；在目录子项/本地操作区显示。worktree 仍是可选择的创建方式及资源类型，不再是会话必须理解的上层单位。                                                                                                                                       |

删除的产品概念：工作区行上混合的“会话 MR + checkout 行数”、一个会话只有一个“当前分支”的假设、从 workspace 反选唯一会话的规则。同时删除全局 Git 来源模式；保留显式目录操作，取舍见第 5 节。

数据关系（示意，不是已实现 schema）：

```text
AgentRecord（现有）
  id / title / provider / cwd / workspaceId / timestamps / lifecycle
  PR/MR 关联（沿用 WORK-328）

SessionContext（新增，每 agentId 一份）
  launchDirectory
  projectId: host-local project FK | null
  pinnedAt / sidebarLabelNames[]
  linkedDirectories[]: { path, source: manual|worktree, addedAt, evidence? }
  autoLinkDirectories / excludedDirectoryPaths[]

WorkspaceRecord（保留）
  id / cwd / projectId / worktreeRoot / lifecycle / terminals ...

客户端 SessionView（每设备）
  selectedSession = serverId + agentId
  selectedTarget = conversation | directory(path, files|changes) | changeRequest(key)
  展开、MR 选择、文件导航、面板位置、会话视图布局
```

`SessionContext.projectId` 是新的会话分组 FK，不改 `WorkspaceRecord.projectId`，也不从 live remote、MR 仓库或绑定路径重新计算。跨 host 仅用已有 projectKey 合并显示，不能用客户端计算出的 remote 冒充 projectId。一个会话只在一个主项目分组出现；跨仓工作在其子项体现。允许手动“未分组”，孤儿项目显示待修复状态并允许重新选择，不能让会话从侧边栏消失；删除项目需先给出受影响会话的去向。

把新增上下文保存到独立 `$PASEO_HOME/agent-contexts/{agentId}.json`，用现有 Zod 和原子写、store 内串行 mutation。理由是旧 agent schema 会过滤未知字段，旧 daemon 重写 agent record 可能丢失新数据。WORK-328 已有的 MR 数据保持原存储权威，不在上下文里再复制。目录相关与会话展示元数据可共用这一文件，替代 WORK-364 尚未实施的单独 agent-directories 文件；不造版本迁移框架。缺文件才初始化，损坏/无权限不能当成空值覆盖。遗留导入的固定时点见第 5 节，存储规则见 [data-model.md](data-model.md#session-context)。会话标签引用现有 host 标签目录，但赋值独立于工作区标签；重命名/删除标签必须扩展现有 store 的串行、可恢复复合事务，不能把两边更新交给组件分别写。

目录按服务端 OS 词法绝对化、精确路径去重，沿用 exact-root 约定，不用 realpath、remote 或分支替换持久身份。启动目录与额外绑定目录合成展示列表，最多 32 项（含启动项）；只支持会话所在 daemon 的目录，跨 host 绑定留后续。MR 的 host 可以不同，不因此获得该 host 的本地文件访问。

手动新增先校验目录存在、类型和权限；允许非 Git。自动新增仅接受可信发起 agentId、成功结果和确切目录的 worktree 创建事件。现有 `paseo-worktree-service.ts` 有 workspaceId/callerWorkspaceId，缺精确 agent 上下文，实施时必须补齐。任意 shell `git worktree add`、磁盘发现或 transcript 文本不自动关联；无证据由用户手动绑定。移除的自动项记排除，重放不再加回；手动重新绑定解除排除。创建新会话的 worktree 先属于新会话的启动目录，不自动给父会话或同 workspace 的所有会话加关联。

生命周期边界：归档会话仍调用 agent 生命周期，保留目录/MR 关联供历史读取；不能把普通“归档会话”接到 archive workspace 而归档同容器的其他会话。关闭会话视图也不等于归档。移除目录只删关联，不删文件、不停止会话；绑定不增加 worktree 保活引用，现有显式配置的 autoArchive/workspace 清理行为保持，并在相关入口说明影响。清理目录仍是独立、明确的资源动作，展示所有已知受影响会话/终端及本地更改，不能从“移除绑定”触发。将来若要绑定就保活，要另行改变资源生命周期，不能悄悄当成 UI 变更。

## 3. 信息架构与四个表面的线框图

**侧边栏：项目 → 会话 → 目录 / PR/MR。** 默认会话折叠，点击标题打开聊天，点击独立展开按钮展开；目录行点击打开文件，行菜单/紧凑布局长按可选“本地更改”。MR 行点击打开远端详情，可进入它的远端更改。导航子项要可用键盘与触摸操作，不能只在 hover 提供入口。

```text
+ 新会话                     搜索 / 历史
筛选：主机 · 项目 · 标签        分组：项目 ▾

▾ works                               +
  ▾ ● slime 与 gmi 联调       需输入   ⋯
      目录
        ~/works              启动 · 执行
        ~/works/slime        main     ⋯  → 文件 / 本地更改
        ~/works/gmi          feat/x   ⋯  → 文件 / 本地更改
        + 绑定目录
      PR/MR
        host-a/team/slime · MR !86    open
        host-b/team/gmi · MR !143     merged
        + 关联 PR/MR
  ▸ ○ 对比配额接口            已结束   ⋯

▾ gmi
  ▸ ● 修复超时                运行中   ⋯
  ▸ ○ 调研资源回收            空闲     ⋯

▸ 目录与终端              （已有独立资源，无须虚构会话）
添加项目 / 主机 / 设置
```

同一路径可以在多个会话下面如实出现；不把它们合并成一个会话。目录项展示简短路径和分支，详情/操作前可见完整路径及主机。多仓库同名目录、同编号 MR 必须可区分；长列表按类型折叠，不默认展开 100 个 MR。折叠会话的摘要可显示“2 个目录 · 2 个 MR”和时间，不把全部关联请求的增删量相加。主机标识延续现有自动多主机门控、Show Host 与每主机 appearance 规则，不加第四个开关。

根会话使用现有根/子会话识别策略作为起点：同容器内部子会话继续在父会话的子会话轨道，已有可独立打开/跨 workspace 的子会话遵守既有可见性规则，不因改侧边栏改变 parentage 或归档级联。私有 helper 不出现，Show background 延续原语义。一个 workspace 中两个顶层会话必须是两行。

置顶改为会话置顶；每个项目内置顶在前、按已保存置顶顺序，然后按创建时间或最后人工 prompt 排序，时间相同用 agentId 稳定打散。最后 prompt 直接取会话自己的 lastUserMessageAt，缺失取创建时间；打开目录、agent 输出和自动消息不改变该排序。状态分组保留，但分组成员改为会话，每行状态来自自己的 activeTurn/permission/attention；不借同 cwd 或 sibling 会话状态。主机/项目/标签筛选保留，组合过滤会话；搜索命中子目录/MR 时显露其所属会话，不能只剩一条失去上下文的子项。项目顺序继续用现有 opaque 分组键。

**右侧 Explorer 与内容面板：始终表明当前浏览目标。** 沿用现有 Explorer、主面板、On the side 的放置偏好与 compact sheet/overlay 宿主，不另造一种面板。宽屏文件/diff 内容可在中间或右侧现有宿主打开；窄屏导航后收起左侧覆盖层，进入对应 Explorer/内容视图，Back 返回该会话，不能意外换会话。

```text
会话：slime 与 gmi 联调                  返回聊天
目标：[ ~/works/slime ▾ ]     [文件] [本地更改]
  主机 srv-A · /home/me/works/slime · main
  文件树 / staged / unstaged / untracked
  此目录的更改可能包含其他会话或工具的内容
  [提交] [推送] ...               （只在本地更改区）

或点击 MR 后：
会话：slime 与 gmi 联调
目标：[ host-a/team/slime · MR !86 ▾ ]
  [概览] [远端更改] [活动 / 检查]
  feature → main · 固定比较版本 · 刷新
  文件树 / 远端 diff               [在 forge 打开]
```

目录点击是一个明确导航意图 `(serverId, agentId, path, view)`，同时选中所属会话并打开该路径；不写全局 active cwd，不重归 workspace，不触发 provider 恢复或切换。Files 仍是路径浏览器，其默认目标是启动目录/该会话最后明确选过的绑定目录。非 Git 目录有文件页，本地更改页说明“此目录不是 Git 仓库”；目录失效保留灰色行并提供重试/移除，MR 和聊天仍可读。

目录可用性、离线、无权限、Git 错误不能当作零改动。多个绑定路径落到同一 checkout 时，本地更改明确显示解析后的 checkout 根与操作范围；重复观察可合并，路径项不合并。仓库被替换时清除旧 Git/MR 比较缓存并重新校验操作目标。绑定路径不是永久仓库身份。

会话“更改”入口默认列出关联 PR/MR，并提供目录的本地更改入口；无关联时显示空态和“关联 PR/MR / 浏览目录”，不自动切成某个 checkout。初次选最近关联的 open 请求，其后保持用户选择；轮询/合并不跳选。独立打开的文件或 MR 面板固定完整对象，切会话不悄悄重绑定；侧栏中跟随会话的目标选择则读各自保存状态。

本地提交/推送/拉取/丢弃/暂存/切分支只作用于可见的真实路径。现有 `git/actions-store.ts` 的提交可能 addAll，必须标明整个 checkout 范围，不能称“提交本会话更改”。切换目标后的旧响应不能写入新面板；未保存文件、review 草稿沿用现有 guarded close，不能在导航时丢失。MR 远端 diff 初期只读，不复用按 cwd 定位的 merge/auto-merge 或本地写按钮。

**Composer：提示属于会话，执行位置单独可见。**

```text
发给：slime 与 gmi 联调
[输入任务……                                      发送]
[Codex / 模型 / 权限]  [执行：~/works]  [2 个关联 PR/MR ▾]
                                      └ 仓库分组列表，点击导航
```

有一个 MR 时可显示“仓库 · MR !86 · 状态”；多项显示数量和选择器，无 MR 时隐藏该提示。分支只有在明确某个 MR 时以 head → base 显示，或在明确目录的本地区显示；不展示“会话当前分支”，不以 cwd 的行数补远端统计。浏览 slime 时执行提示仍是 `~/works`；必要时显示“浏览：slime”以帮助区分。切换浏览目标不重置草稿/附件。

当前 composer 的 cwd 查询还用于附件搜索和 forge 识别（`composer/index.tsx`），不能因移除展示提示而全部删除。附件检索必须保留显式仓库上下文，目录附件带完整路径，远端 review 上下文带 MR 身份/比较版本。

**设置：配置展示与行为，不用全局模式决定对象归属。**

```text
设置 › 侧边栏
  分组                 项目 / 状态
  排序                 创建时间 / 最后人工消息
  显示                 主机、关联数量、时间、服务…
  Header / Footer      沿用现有可排序隐藏项

会话 ⋯ › 会话设置
  项目                 works ▾
  标题 / 标签 / 置顶
  目录                 启动目录 + 绑定管理
  自动关联新建目录      开（只接成功且有发起会话证据的操作）
  PR/MR                沿用 WORK-328 关联管理与自动开关
  执行目录             ~/works（本期只读）

设置 › 面板
  Changes / PR 打开位置、diff 布局、换行…  沿用
  Git 信息来源         删除；已确认
```

执行目录切换在模型里有明确位置：会话设置的“执行目录”，将来可由 Composer 的执行位置提示进入同一入口；不能挂在“浏览目录”选择器里。界面切片只显示真实执行位置，不开放切换，也不放一个无法工作的按钮。

事实：`agent-sdk-types.ts` 的 config 有 cwd，公共 AgentSession 没有切换 cwd 接口；Codex `codex-app-server-agent.ts` 构建 turn/start 参数时会传 config.cwd。因此技术上有接入点，不能断言不可能；但需另行验证 provider 恢复、idle/排队/steer 互斥、sandbox roots、目录指令与 MCP 重载、持久化及失败回滚。目录绑定和 UI 导航不依赖这些问题解决。

## 5. 兼容、迁移和旧端

迁移要保留已有资源，而不是把每个 workspace 机械变成一个会话。

1. 首次升级启动在开放客户端之前固定现存会话集合，补齐缺失的 SessionContext 并完成遗留置顶/标签导入。启动目录取已记录 cwd，项目取 owning workspace；title 仍用 agent.title。导入完成标记只在整批成功后保存，中断重试保留已初始化的用户值。之后的新建/导入会话和普通缺文件读取只初始化启动目录与项目，置顶和标签为空，不再继承 workspace 的值。重放和并发首次读取不会覆盖用户已选项目/绑定；不能确认的历史目录不伪造。
2. 一个 workspace 的多个根会话逐条呈现，共享 cwd 逐条保留。旧 workspace 标题只在仅有一个可见根会话且 agent 无自有标题时作为一次性/种子；多会话不把同一标题强写给全部会话。旧 workspace 置顶/标签可一次性复制到其各个可见根会话，保留原排序并以创建时间/ID 稳定展开；之后互相独立。已有会话自身标题和已经初始化的上下文优先，旧客户端之后改 workspace 标签不会反向覆盖会话。导入标记与数据同原子保存。
3. 项目顺序、主机/项目筛选、标签目录和排序偏好延续；旧 pinnedWorkspaceOrder 用初始化时明确的 workspace→会话列表展开成新 per-device 会话顺序，旧键继续接受读取但不再作为新导航权威。多会话有相同标签/置顶是显式迁移结果，不是实时共享。
4. workspace 布局、终端 ID、运行服务和插件面板不丢弃。旧布局继续原样保留，新的会话浏览状态按 `(serverId,agentId)` 存到独立命名空间；切两个同 workspace 会话时各自恢复目标，不复制运行中的终端进程。终端、脚本仍由内部容器管理；从明确目录新建终端时显式选/创建其资源容器，不能通过“绑定目录”就隐式启动终端或执行 setup。没有可见根会话的已有终端/服务/文件标签，保留在“目录与终端”资源入口，直到用户明确清理，不伪造聊天。
5. session 路由意图仍经过现有 host 边界和导航 owner；不在叶子组件拼 route 或覆盖全局 active workspace。旧 `/workspace/...` 链接继续打开原容器及原标签，不随便选一个会话；显式 agent 链接打开该会话。新记忆保存会话和完整目标，遵守 host 首先挂载、等待 hydration、离线不跳主机、Android Back 与 guarded close。原“最后工作区”保留为兼容恢复输入，不用它覆盖新已保存会话。
6. 旧 app 连新 daemon：保留旧 workspace/agent wire 和生命周期接口，不移除/收窄字段，不向未订阅旧端推未知新事件。旧 app 的 workspace 显示仍是旧语义；新 app 的会话项目独立，不能靠重写老 FK 来模拟。二进制降级忽略但保留新侧文件，再升级恢复；新端删除会话后清理其侧文件，旧端删除造成的孤儿只能在核实 agent 真正不存在后清理，不复活会话。
7. 新 app 连旧 daemon：统一导航所需的新上下文/目录能力在一个 host 边界检测，提示更新以使用会话目录树；该 host 的原聊天、明确 cwd 的文件/Git/终端入口仍可进入，但不拿 cwd 拼出一份声称完整的多目录关联。混合版本按 host 给出明确能力状态，不加一个面向所有用户的旧导航模式。MR 摘要、远端 diff、远端活动仍各自用独立能力 gate；缺详情能力就外链/提示更新，不拿 checkout 内容替代。

daemon capability `sessionContext`，以 dotted `agent.context.*.request/.response` 和明确观察契约提供上下文管理；MR 状态沿用 `agentChangeRequests`，远端 diff/详情另立能力。新增 wire 字段 optional、纯结构，不新增 transform/catch/preprocess。磁盘初始化、旧 app parsing 与功能 gate 分别验证；不是加一个 feature flag 就完成兼容。

按路径的**操作**必须保留：文件、Git、终端、脚本、worktree 清理都需要明确真实目标。按路径的**全局模式**删除：同一树已经同时表达会话关联和目录事实，全局开关会使行的意义随设置变化，还让跨仓会话重新退回启动 cwd。具体替代入口是侧栏目录子项及“目录与终端”，不是取消用户直接使用目录的能力。原全局开关已确认删除；任何后续目录资源偏好只能定义为“显式目录资源入口的显示偏好”，不要让会话行变回 checkout 行，也不要自动回落。

请求量和状态归属是整体约束：会话关联快照按 `(serverId,agentId)` 共用有引用计数的观察；相同 MR 沿用 WORK-328 daemon 身份去重和预算。侧栏只为可见且确实显示摘要的会话请求 MR 状态；一个订阅会保留其全部关联 MR 的成本需计入预算。目录列表不用每条持续 stat/watch；展开/恢复/手动刷新时有界检查，文件/Git 只观察实际打开的路径，隐藏/后台释放。不能让新树制造“会话数 × 绑定目录数”的 watcher。远端 diff/活动/检查只加载选中可见请求，分页/限体积；比较缓存含完整身份与 base/head/比较基线，支持 force-push、目标分支更新、binary/rename/截断。目录内容缓存继续按 `(serverId,path/checkout)` 共享，UI 选择与草稿按会话+目标隔离；同 MR 的公共数据可共享，review 草稿还带比较版本。
